FieldShift Phase 2 — NASA POWER data pipeline

IMPLEMENTED
- Fetches NASA POWER Daily Point API data for configurable coordinates and date ranges.
- Validates latitude, longitude, and start/end dates.
- Uses a 30-second request timeout and reports connection, HTTP, invalid JSON, missing-field, and empty-response errors.
- Returns date, temperature, temp_max, temp_min, rainfall, humidity, wind_speed, solar_radiation.
- Parses dates and numeric values; converts NASA's -999 missing marker to NaN without substituting zero.
- Detects latest valid observation based on at least one valid environmental measurement, not the latest calendar date.
- Saves cleaned output to a coordinate/date-named CSV in data/nasa_power/.
- Provides a recent-window helper with configurable processing delay.
- Retains src.nasa_power compatibility imports and command-line execution.
- Adds mocked unittest coverage; no new dependency was required.

Latest valid observation in the example run: 2026-09-29. The next calendar
days were not used; latest-valid detection ignores rows only when all
environmental measurements are missing. In this returned data, Sep 29 had
valid temperature and other measurements although solar radiation was NaN.

MISSING VALUES
Every numeric field equal to NASA POWER's -999 marker is converted to pandas
NaN during fetch and CSV preparation. Missing values remain missing; they are
not converted to zero. The saved example CSV contains no -999 marker.
